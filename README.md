# Visual Match Montage · 视觉穿越与配乐混剪

让观众的视线留在同一处，画面连续变成不同的世界。

这是一个面向 Codex 的中文创作 skill：从参考图片提取视觉锚点，生成跨题材构图呼应，筛选素材，再按配乐编排硬切、分块替换与拼图混剪。

## 能做什么

- **跨题材形状穿越**：眼睛、湖泊、星系、日用品之间切换，保持主要位置、比例和方向的呼应。
- **固定人物穿越**：以人物身份参考约束多世界变体；此模式仍需实际小样验证。
- **配乐混剪**：从素材检索、音乐分析到时间线、试渲染和成片检查。

默认创作方向是“主题为主，在关键切点插入意外题材”。例如虹膜 → 日冕 → 地球 → 洗衣机滚筒 → 旋涡星系。具体主题和风格始终以用户要求为准。

## 安装

在终端执行以下命令，将仓库克隆到 Codex 的 skills 目录：

```sh
mkdir -p "${CODEX_HOME:-$HOME/.codex}/skills"
git clone https://github.com/cshinjnu-eng/visual-match-montage.git \
  "${CODEX_HOME:-$HOME/.codex}/skills/visual-match-montage"
```

如果目标目录已经存在，先检查已有版本，避免覆盖本地修改。安装后在新会话中调用：

```text
使用 $visual-match-montage，以这张照片为参考，先给我有主题和大跨度两组代表样图。
检查主体可信度、构图对应和语义跨度，让我看样图选择后再扩展。
```

已有素材时也可以直接要求检查与剪辑：

```text
使用 $visual-match-montage，检查这组图片能否做视觉中心稳定的连续穿越。
先报告需要修改的图片，再按我提供的配乐制作短片试剪。
```

## 质量门控

检查顺序为：**主体可信 → 构图对应 → 语义跨度 → 序列连续**。

每项记录 `pass / revise / reject / unverified` 和具体理由。生成成功或单张好看，不代表能直接剪成连续穿越；关键项未通过，不进入正式素材池。不存在经过标定的通用构图合格分数。

## 工具与依赖

- 默认使用执行环境中可用的 Codex 内置 `image_gen`；实际参数遵循当时的工具定义。
- `jmate-image` 是原项目使用过的可选后端，本仓库不包含其服务、安装配置或凭证，也不要求用户安装它。
- 视频阶段可沿用已有渲染工具。来源项目用 Python、Pillow、NumPy 和 FFmpeg；本仓库包含工作方法，不提供通用视频渲染程序。
- Skill 本身不提供模型、API 额度或音乐素材。单图创作无需先准备配乐。

## 当前验证范围

已做 skill 结构校验、指令审查及实际生图小样。一次 GPT-6 Luna 独立试作生成了眼睛参考、湖泊和洗衣机两张关联图，并将构图不匹配标为需要修改。

这证明工作流能指导初步创作与筛查，不等于整套流程已端到端验收。公开版未附原项目的私有记录、图片、配乐或旧脚本；连续试剪、固定人物模式和新作品的音画同步仍需按任务验证。
